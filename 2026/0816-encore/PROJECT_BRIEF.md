# 0816-encore — 予約された動きだけでできた影絵劇場

## 意図

`Tween` は「いま動かす」ではなく**「こう動けと予約する」**API だ。
その性質をいちばん素直に持っている場所が舞台だと思う——幕が上がる時刻、役者が袖から出る
きっかけ、繰り返す所作、幕を引く合図。すべてが上演の前に決まっている。

だからこの作品は影絵の小劇場にした。**動くものは 1 つ残らず `Tween` に予約されている。**
座標を毎フレーム計算している箇所は無い。

## 想定する動作

舞台が 2 面ならぶ。**振付も刻み方もまったく同じ**で、違いは 1 か所だけ——
アンコールのときに `tweenManager` へ**登録し直すか**。

| | 座組 甲「預けたまま」 | 座組 乙「呼び戻す」 |
|---|---|---|
| 開演 | `add` → `start()` | `add` → `start()` |
| アンコール | `reset()` → `start()` | **`add()` し直してから** `reset()` → `start()` |

1 公演目は見分けが付かないはずだ。両方とも幕が上がり、役者が 3 人ずつ袖から出て、
扇を開いて所作を繰り返し、会釈して、幕が下りる（1 公演 = 約 17.2 秒）。

アンコールを掛けたときに差が出るなら、それは `TweenManager` が完了した `Tween` を
配列から外すからで、外れた `Tween` に `start()` を掛けても誰も `update` を呼ばない。
`Tween.update(_:)` は `internal` なので、利用者が手で進めることもできない。

舞台の下に**進行表**が出ている。各 `Tween` の状態と値がそのまま読める。
「実行中と書いてあるのにバーが動かない」行が出たら、それがこの作品の主題だ。

## 検証したいこと

`Tween` / `TweenManager` / `Interpolatable` は、このスケッチブックの既存 14 作品で
ほぼ手つかずだった（`tween()` を明滅に 1 回通しただけ）。だから
`delay` / `repeatCount` / `yoyo` / `onComplete` / `cancel` / `reset` と、
それらの**組み合わせ**を作品として通しにいく。

裏では `Instrument.swift` が同じ API を固定刻みで叩き、判定を `PASS` / `FAIL` で出す。
**舞台に出る異常と、判定表の FAIL は同じ現象**であることを見せたい。
