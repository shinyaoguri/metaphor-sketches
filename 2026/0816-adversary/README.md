# 0816-adversary — 敵対的仕様適合検査盤

metaphor の API を「作品を作る過程でたまたま踏む」のではなく、**敵対的に組み合わせて仕様に反する動きを炙り出す**ための検査盤。
55 の検査が 6 面に並び、**スケッチ自身が `loadPixels()` で実際のピクセルを読んで期待と照合**し、PASS / FAIL を判定する。

FAIL が赤く残る画面そのものが作品の主題で、同時に metaphor の回帰検査盤としても使える。

![面 F。F6 / F8 / F10 / F11 が赤枠で FAIL](https://i.gyazo.com/374ccabbdbafc33b37a7ff92d39e3fc3.png)

## 走らせる

```bash
tools/probe.sh cycle     # 起動 → 全面を判定 → frame.json から合否を抜いて表示
tools/probe.sh shot F    # 面 F を表示した状態で PNG を撮る (F 5 でセル単位に切り出し)
tools/probe.sh stop
```

`metaphor run` でも動く（キー `1`–`6` で面切替、`r` で再判定）。
判定結果は **frame.json の `custom` が一次証拠**で、`check.<ID>` に全件、`summary.*` に集計が載る。画像は FAIL の裏取りにだけ使う。

## 作り

```
Harness.swift    Check / Verdict / PixelReader (ink の外接矩形・被覆率・行プロファイル)
PlaneHelpers.swift  期待色・期待矩形・数値の照合と、プロファイル相関
App.swift        面の巡回・格子レイアウト・枠とラベル・probe 出力
PlaneA…F.swift   面ごとの検査
```

肝は **1 フレームに `loadPixels()` を 1 回だけ**呼ぶこと。全セルの検査図形を描き切ってから読み戻し、その 1 枚から各セルの領域を読んで一括で判定する（`loadPixels()` はレンダーパスを分割して GPU 完了を待つので、セルごとに呼ぶと重い）。枠とラベルは判定の**後**に描くので読み戻しを汚さない。

検査は時間に依存しない（毎フレーム同じ絵になる）ので、判定は面ごとに 1 回で足りる。

## 実測（2026-08-16）

| 対象 | PASS | FAIL |
|---|---|---|
| **v0.9.0**（当時の最新リリース） | 49 | 6 |
| **main**（v0.9.0 + 未リリースの修正） | 50 | 5 |

依存を `swift package edit metaphor --path <metaphor のチェックアウト>` でローカル main に差し替えて同じ検査を回し、差分を機械的に取った。差は F11 の 1 件だけで、残り 5 件は main でも再現する。

### 堅かったところ

面 A・B・C・E は全 36 件が PASS。特に:

- **状態スタック**は Processing の 3 系統（変換 + スタイル / 変換のみ / スタイルのみ）を正しく守備分けし、スタックを交差させても 8 段入れ子にしても壊れない
- **退化した引数**（負のサイズ・逆転した corners・サイズ 0）は Processing と同じく正規化される
- **`screenX/Y` は実際に描かれた ink の位置と一致**する（translate → rotate → scale の合成下で差 1px 未満）。2 引数版と 3 引数版も一致
- **合成の数値**が式どおり。加算・乗算・差分・アルファ（`rgb(128,100,0)` 期待 `rgb(128,99,0)`）まで合う
- **`textWidth()` と実描画幅**が 3px 以内で一致（151 に対し 148）

## 着手時のプラン（記録）

**前提**: これまでの作品駆動検証（[#414](https://github.com/shinyaoguri/metaphor/issues/414)）で見つかった穴は「作品を作る過程でたまたま踏んだもの」に偏っていて、状態スタック・描画モード × 退化した引数・変換の数値・色空間・テキスト計量は誰も確かめていない。そこを敵対的に潰す。

**方針**: 「見た目がおかしい」で止めず、スケッチ自身がピクセルを読んで期待と照合し、合否を frame.json へ出す。AI が snapshot 1 枚 + frame.json で全件を読めるようにする。

**検討して採らなかった案**:

- *セルごとに `loadPixels()` を呼ぶ* — 素直だがレンダーパスが検査の数だけ分割される。全セルを描き切ってから 1 回にした
- *目視で判定する* — 55 件を毎回人が見るのは続かない。数値に落とせない検査だけ `LOOK` に落とす設計にした（最終的に 0 件）
- *最初から数値照合だけを狙う* — 面 A・B を実装したら 18/18 PASS で、実装の素の堅さを測るだけになった。そこで面 C 以降は「ライブラリが自分で返した数と実際に描いたピクセルの一致（内部矛盾）」を突く方向へ設計し直した。`screenX/Y` の照合と `textWidth` の照合がこれにあたる

**判定を書くときの落とし穴**（実際に踏んだ）:

- **FAIL の原因を判定メッセージに書き込むと、間違った原因のまま記録が残る**。F10 は最初「leading を倍率として扱っている」と書いたが、真因は「折り返しが効かない」だった。原因が確定するまではメッセージを実測（何が何 px だったか）に留めるほうがよい
- **同じリソースを複数の検査で共有すると、検査どうしが干渉する**。F7 は F8 / F9 と `Graphics` を共有していたせいで本来の検査（親のスタイルを継承しないか）が測れなかった。専用バッファに分けたら PASS になり、代わりに共有側（F8）が [#745](https://github.com/shinyaoguri/metaphor/issues/745) を炙り出した
- **弱い判定は FAIL を取りこぼす**。F11 の反転は最初 ink の重心で見ていて PASS していた（"Ag" は反転しても重心が動かない）。行ごとの ink 量プロファイルを取り、そのままと上下反転で相関を比べる形にして初めて検出できた
- アンチエイリアスで外接矩形は 1px 膨らむ。`tol` は 3–4px 程度に取る
